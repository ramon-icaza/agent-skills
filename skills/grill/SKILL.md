# Скилл `grill` — прожарка идеи

## Назначение

Прожарка — это метод итеративного сокращения области неопределённости в идее. Агент определяет границу того, что ещё не известно или не уточнено, и задаёт пользователю вопросы, которые позволяют сдвинуть эту границу так, чтобы неопределённости стало меньше.

Каждый такой цикл называется **раундом**. Раунды повторяются снова и снова, пока область неопределённости полностью не исчезнет. После этого агент докладывает пользователю, к чему они пришли, и спрашивает, согласен ли пользователь. Прожарка считается оконченной только при двух условиях одновременно:

1. Область неопределённости исчезла (все границы сдвинуты, все неизвестности устранены).
2. Пользователь явно подтвердил, что согласен с итоговым докладом агента.

## Когда применять

- Пользователь сформулировал идею, но в ней остаются неясности, пробелы или недоговорённости.
- Нужно систематично выявить все скрытые допущения и риски перед началом реализации.
- Идея требует последовательного уточнения деталей через диалог с пользователем.

## Основные принципы

### 1. Граница неопределённости и раунды

На каждом раунде агент:
- Определяет текущую границу неопределённости (что ещё неизвестно или не уточнено).
- Формулирует набор вопросов, ответы на которые сдвинут эту границу.
- Передаёт вопросы пользователю (или субагентам, см. ниже).
- После получения ответов пересматривает границу и начинает следующий раунд, если неопределённость осталась.

### 2. Не спрашивай то, что можно найти самому

Агент **не задаёт пользователю вопросы**, ответы на которые он (или субагенты) может найти самостоятельно — например, в документации, коде, репозитории, открытых источниках или через анализ существующих артефактов.

Для таких вопросов агент вызывает **субагентов**, которые ищут ответы самостоятельно. Агент подводит итоги их работы и использует полученные данные для сдвига границы неопределённости без лишнего привлечения пользователя.

### 3. Сквозная нумерация вопросов

Все вопросы в рамках сессии прожарки нумеруются сквозно: Q1, Q2, Q3, Q4 и так далее. Нумерация не сбрасывается между раундами.

### 4. Рекомендуемый вариант ответа и формат «да»

Каждый вопрос формулируется таким образом, чтобы ответ **«да»** означал выбор **рекомендуемого варианта ответа**. К каждому вопросу агент даёт рекомендуемый вариант ответа (по умолчанию — «да», если вопрос сформулирован правильно).

Пример правильной формулировки:
```
**Q3:** Предполагается ли, что система должна поддерживать одновременную работу не менее 1000 пользователей?
- Система должна поддерживать одновременную работу не менее 1000 пользователей.

---

**Q4:** Следует ли логировать только запросы, звершившиеся ошибкой?
- Следует логировать только запросы, завершившиеся ошибкой. Успешно обработанные запросы логировать не следует. 
```

Ответ «да» подтверждает рекомендуемый вариант.

### 5. Запрет на внесение изменений

В рамках прожарки агент только исследует и планирует. Внесение изменений **запрещено**.

## Процесс прожарки

### Раунд N (повторяется пока есть неопределённость)

1. **Определи границу неопределённости.** Составь список того, что ещё неизвестно, не уточнено или недоговорено в идее.
2. **Раздели вопросы на две группы:**
   - Вопросы, ответы на которые агент/субагенты может найти самостоятельно → передай их субагентам.
   - Вопросы, которые требуют уточнения у пользователя → сформулируй их для пользователя.
3. **Задай вопросы пользователю** в формате:
   ```
   - **Q<номер>:** <Текст вопроса>
   - <Рекомендуемый ответ>
   ```
   Убедись, что «да» соответствует рекомендуемому ответу.
4. **Собери ответы** (от пользователя и от субагентов).
5. **Пересмотри границу неопределённости.** Если она ещё не исчезла — начни следующий раунд (N+1).

### Завершение прожарки

Когда область неопределённости полностью устранена:

1. Агент представляет итоговый доклад пользователю и спрашивает: **«Согласны ли вы с итоговым докладом?»**
2. Прожарка считается оконченной только после **явного подтверждения согласия** пользователем.

## Результат

По окончании прожарки появляется согласованный с пользователем итоговый документ, в котором нет неопределённостей. Этот документ может быть передан в скилл `handoff` (опционально) или использован напрямую, если прожарка самодостаточна.
