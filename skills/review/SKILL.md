# Скилл `review` — проверка кода

## Назначение

Проверить код (или изменения) по чек-листу требований. Скилл используется как этап качества в конвейере `implement` (и в цикле `tdd`), а также может быть вызван пользователем отдельно.

## Требования к коду

Код должен соответствовать всем пунктам ниже:

1. **Нет багов и решает поставленную задачу.** Код выполняет именно то, что требуется, и корректно обрабатывает ожидаемые и граничные случаи.
2. **Нет уязвимостей.** Отсутствуют SQL-инъекции, XSS, path traversal, небезопасная десериализация, утечки секретов, проблемы аутентификации/авторизации и другие типичные уязвимости.
3. **Производительность и оптимизация.** Код не содержит очевидных узких мест (N+1 запросы, синхронные блокирующие операции в асинхронном контексте, неэффективные алгоритмы с большой временной или пространственной сложностью) и не будет существенно замедляться при высокой нагрузке.
4. **Опасные места покрыты тестами.** Все неочевидные, критически важные или склонные к ошибкам участки кода имеют автоматические тесты.
5. **Diff компактен и понятен.** Изменения минимальны, не содержат лишних правок (форматирование unrelated кода, комментированный код, временные отладочные конструкции), легко ревьюятся.
6. **Нет неиспользуемого функционала (YAGNI).** Нет кода, который «может пригодиться в будущем», но не требуется текущей задачей.
7. **Нет самописных аналогов стандартной библиотеки или используемых в проекте библиотек.** Не изобретайте велосипеды там, где уже есть надёжное решение в stdlib или в зависимостях проекта.

## Процесс ревью

1. Ознакомься с задачей и контекстом (что должен делать код).
2. Пройдись по файлам и изменениям, проверяя каждый пункт чек-листа выше.
3. Для каждой найденной проблемы укажи:
   - Файл и строку (или фрагмент).
   - Какое требование нарушено.
   - Почему это проблема.
   - Рекомендацию по исправлению.
4. Если критических проблем нет — подтверди, что код прошёл ревью.
5. Если проблемы есть — верни их в виде списка задач на исправление, чтобы агент мог спланировать доработки.

## Результат

- **Пройдено** — код соответствует всем требованиям, замечаний нет.
- **Требуются исправления** — структурированный список проблем с указанием файлов, строк и рекомендаций.

При отрицательном результате не изменяй код сам — просто сформулируй замечания. Исправления вносит агент, вызывающий этот скилл (или подчинённый агент по указанию главного).
