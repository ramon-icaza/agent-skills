# Скилл `tdd` — разработка через тестирование

## Назначение

Реализовать функционал, следуя циклу Red → Green → Review. Скилл вызывается субагентом, получившим подзадачу на написание кода в рамках скилла `implement`.

## Цикл TDD

Выполняй итеративно до тех пор, пока функционал не будет полностью реализован и пройдёт ревью:

### 1. Red — напиши фейлящийся тест

- Перед написанием любого решения создай тест (или несколько тестов), который описывает ожидаемое поведение нового кода.
- Тест должен падать (быть «красным»), так как реализации ещё нет или она неполная.
- Убедись, что тест падает именно из-за отсутствия/некорректности функции, а не из-за ошибки в самом тесте.

### 2. Запусти тест — убедись, что он красный

- Запусти соответствующий тестовый фреймворк.
- Подтверди, что тест не проходит.

### 3. Green — напиши решение

- Напиши минимальный объём кода, необходимый для прохождения теста.
- Не стремись к идеальной архитектуре на этом этапе — цель сделать тест зелёным.

### 4. Запусти тест — убедись, что он зелёный

- Запусти тест снова. Он должен пройти.
- Убедись, что не сломались существующие тесты (регрессии).

### 5. Review — циклически вызывай review в субагенте

- После того как тест зелёный, вызови субагента с скиллом `review` для проверки написанного кода и тестов.
- Если review выявит проблемы:
  - Исправь найденные проблемы.
  - Запусти тесты снова, убедись, что они по-прежнему зелёные.
  - Повторно вызови `review`.
- Повторяй цикл до тех пор, пока `review` не подтвердит, что код соответствует всем требованиям.

### 6. Повтор для следующего функционала

- Если функционал ещё не завершён, вернись к шагу 1 для следующего теста/возможности.

## Результат

- Написаны и проходят все тесты для функционала.
- Код прошёл проверку скиллом `review` без критических замечаний.
- Diff компактен, содержит только необходимые изменения.
